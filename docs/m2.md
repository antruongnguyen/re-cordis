# M2: root-scoped effects, typed events, and diagnostics

This records the M2 boundary. [M5](m5.md) now supplies the scoped service and
internal-update protocols identified below as later work.

**M2's root-level contract is complete**, including synchronous cleanup timing
and effect-tree introspection. [M3](m3.md) subsequently adds plugin Registry,
non-root lifecycle, and per-Fiber ownership to these APIs. This extends
[M1](m1.md), not the independent [M0 models](m0.md),
and retains Rust 2024, the Rust 1.85
minimum, explicit local hosting, and non-owning Context views. No dependencies
were added for M2.

## Effects and resource acquisition

| API | Behavior |
|---|---|
| `Disposer::new(callback)` | Wrap one owned async cleanup. Drop is inert. |
| `Disposer::sync(callback)` / `Context::on_dispose_sync(callback)` | Represent all-synchronous cleanup without introducing an async boundary. |
| `Disposer::compose(children)` | Reverse-order, sequential cleanup. Like the TS composed chain, a failure stops later children; top-level root cleanup still attempts independent siblings concurrently. |
| `Disposer::from_effect(effect)` | Transfer an unclaimed registration from its owning journal into composition without creating a second cleanup claim. Listener/exporter registrations expose `into_effect()` for this. |
| `Context::effect(factory)` | Admit and reserve cleanup ownership before running synchronous setup now; factory returns one disposer, including a composed one. |
| `Context::effect_iter(factory)` | Collect yielded disposers from a synchronous iterator. All-sync partial rollback finishes before this method returns; pending async children continue on the host. |
| `Context::effect_async(factory)` | Run the factory now and start its future on the host; the future produces one disposer. |
| `Context::effect_stream(factory)` | Collect async yielded disposers. Stop before advancing another step after disposal, but retain and clean up the final already-in-flight acquisition. Yield to the local host between steps. |
| `Effect::ready()` | Wait for setup without disposing it. Async setup failure rejects only after partial-acquisition rollback. |
| `Effect::dispose()` / root drain | Manual disposal runs a synchronous chain and any async factory prefix before returning; its completion waits for pending async work. Root drains stay supervised/concurrent. Disposing an async setup waits for its final acquisition and cleanup. |
| `Effect::with_label(label)` | Name the registration; the label follows ownership transfer into a composition. |
| `Context::get_effects()` | Return independent value-only `EffectMeta { label, children }` snapshots of the selected Fiber's journal in registration order (root-only at M2). |

Synchronous cleanup is explicit: use `Disposer::sync`/`on_dispose_sync` when
the callback has no async work. Wrapping an async block in `Disposer::new`
still has an async boundary, even if the body never suspends. Mixed compositions
run in reverse order until their first async child; remaining children run
only after that child succeeds. A child failure stops that composed chain,
but independent root cleanups are still attempted. Returned errors/panics are
reported and preserved in the completion, not converted into successful work.

Synchronous iterator/factory failures return `SetupError` only after the
all-synchronous partial rollback has run. If rollback reaches a pending async
child, the host continues the remainder; use `effect_stream` and `ready()`
when that async rollback barrier must be observed. There is no implicit async
Drop or attempt to force-poll arbitrary async cleanup as synchronous code.

### Effect tree snapshots

Plain acquired disposers are not separate effects. Transferred registrations
become children in acquisition order; nested transferred groups retain their
own trees. Listener labels default to `ctx.on(<event label>)`; exporters use
`ctx.logger.exporter()`; other registrations are `anonymous` until named.
Async yields update the owning node as children are acquired. Siblings not
transferred remain independent root entries. Manual/root claims remove their
root entries immediately, even while async completion is pending.

Snapshots contain only strings and child snapshots, so retaining them cannot
retain callbacks, Context values, acquired resources, or the runtime. A snapshot
never changes after capture. Reading introspection requires a live runtime,
not an admitted run scope. Transfers still require host admission. An active
setup attempting to transfer itself or a composition containing it is refused
as `RecursiveComposition` before the root claim changes, preventing both a
cleanup self-wait and a metadata reference cycle. The guard retains active
setup ancestry through nested factories, not only the innermost callback.
Cancellation prefixes remain eager after transfer into a composition too.

Both root drains and failed-setup rollback attribute cleanup to its owner,
so self-drain is refused rather than deadlocking on setup readiness. User
factories/iterator polling/futures have narrow unwind boundaries; storage
bookkeeping is outside them. Worker failures are supervised separately.

The factory is eager; a native async future's body is still lazy. An async
factory can perform its synchronous acquisition prefix before returning the
future. Initial/final acquired disposers are retained even if the waiter or
registration token is dropped. Host destruction remains cancellation.

## Event contracts, registration, and selection

`Event<A, R>` selects a typed argument/result contract. `Event::named(name)`
shares a string key, with explicit `EventError::ContractMismatch` for an
incompatible live bucket. Names such as `__proto__`, `constructor`, and
`toString` are ordinary strings. `Event::symbol(description)` allocates fresh
identity; cloning shares it, equal descriptions do not. Removing the final
listener removes the bucket and its live contract.

Register with `Context::on`, `on_with`, or `once`. `ListenerOptions` supports
prepend/global. The returned `ListenerRegistration::remove()` synchronously
claims exactly that registration; dropping it is inert. Cleanup removes
the registering Fiber's listeners, including those transferred into composition.

Every mode snapshots the hooks before running user filter/callback code.
`DispatchOptions::filtered` receives the registration Context, including typed
metadata. Global hooks bypass filters; omitting a filter selects all hooks.
There is no automatic ancestor-only routing. Removing a selected listener
does not erase it from an existing snapshot. Once removes before callback
invocation, including recursion; it does not add a later occurrence-claim gate.

Callbacks receive their registration Context explicitly. Arbitrary JavaScript
`thisArg`/Proxy tracing is not simulated. Service-derived filters and traced
definition/use-site access remain M5 work.

## Five dispatch modes with honest callback shapes

| Mode | Contract |
|---|---|
| `emit` | Invoke sync callbacks and async factories before returning. A sync failure stops later invocations. Deferred continuations are already scheduled, even when an earlier-started continuation's waiter is lost due to a later sync error. |
| `parallel` | Invoke every responder/factory immediately, await all outcomes, aggregate every failure in snapshot order. |
| `serial` | Invoke the first responder/factory immediately, await it, then continue in order until an explicit Break answer. |
| `bail` | Invoke synchronous responders in order until Break. Reject an incompatible snapshot before any callback runs. |
| `waterfall` / `waterfall_async` | Around-middleware with a terminal callback and owned one-use next. An omitted next vetoes the remainder; outer frames resume after inner frames. Sync and async chains have explicit callback types. |

`Listener::sync` and `Listener::asynchronous` return `ControlFlow<R>` answers;
Continue means no answer, while `Break(0)` and `Break("")` are answers.
`Listener::around` and `around_async` take `Next<R>` and `AsyncNext<R>`.
Responder and middleware shapes are not interchangeable; mode mismatch is an
explicit `UnsupportedMode`, not a skipped listener. Bail is synchronous-only.
Mixed sync/async around chains currently require explicit adapter callbacks;
there is no implicit coercion between the two waterfall APIs.

`Next` and `AsyncNext` consume themselves. Duplicate invocation is a compile
error, replacing the upstream runtime error; compile-fail evidence covers
both. Event argument mismatches also have a compile-fail example. The general
`events.types.ts` public-type inventory remains M6 work.

Async factories execute their eager prefix now; their returned async bodies
run on the local host. Native `async` closure bodies are not automatically
eager. Async callbacks' prefix panics become deferred callback errors; sync
callback panics become immediate errors. Errors preserve original sources.

Async dispatch returns `EventTask<T>`, a wait-only handle. Emit still reports
synchronous errors directly, but its handle can observe deferred failures.
Dropping handles cannot cancel the workers. Emitted failures are always
diagnosed; serial/parallel/waterfall failures belong to an awaiting caller,
or are diagnosed if their waiter is abandoned. Host cancellation never returns
a successful result. In-flight dispatch survives listener/root removal, but
not host destruction.

## Minimal core logger

`Context::logger(None)` selected root at M2 and now selects the current Fiber's
diagnostic name under M3; `Some(name)` selects an explicit channel.
Logger handles are non-owning and can be used synchronously outside a run
scope. `error`, `warn`, `info`, `debug`, and `with_level` use Rust Display
formatting, not JS printf formatters. Sequence/time/name/level/message/root
identity are structured fields. M3 extends attribution to non-root Fibers.
Automatic callback diagnostics also retain
the original failure source in the record.

The built-in chronological buffer keeps the last **1000** admitted records
and survives reusable root drains. Its default verbosity is Info. Exporters
have independent name-specific/default verbosity overrides. Snapshot buffer
inspection is explicit through `Context::log_buffer()`.

`add_exporter` is owned by the registering Fiber, with exact removal or transfer into
composition. No user exporter/formatter/destructor runs under a storage
borrow. Every selected exporter is attempted even if another fails, returning
`LogError::Exporters` with sources. This attempt-all policy is a deliberate
diagnostic safety strengthening over TS's unguarded export loop.

Cleanup, failed setup/rollback, and abandoned event errors now go through the
structured diagnostic logger as well as stderr and `Runtime::take_failures`.
Broken diagnostic exporters are reported without recursively logging through
the same broken exporters. Their sources are retained too.

Full traced service-call naming, plugin-name normalization, intercept defaults,
formatter/color rules, and error-cause/aggregate flattening remain M5/M6. The
buffer and exporter subset are not a claim of complete `logger.spec.ts` parity.
